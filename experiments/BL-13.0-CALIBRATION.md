# BL-13.0 — Exact Boolean metric calibration

## Purpose

BL-13 must demonstrate that its candidate representation and screening layer reproduces established Boolean-function properties before any Boolean × X generator is allowed to enter the discovery pipeline.

This stage is infrastructure calibration, not a novelty experiment.

## Source of mathematical truth

Exact metrics are delegated to the pinned `scirust-modalg` revision:

`7178bcfc6800e3277b9f16c3f03c70523b53e2c7`

BooleanLab must not maintain a divergent implementation of the Möbius/ANF or Walsh analyses used here.

## Frozen fixtures

### `and_2`

Truth table, packed-input order `00, 01, 10, 11`:

`0, 0, 0, 1`

Required properties:

- input bits: 2
- algebraic degree: 2
- nonlinearity: 1
- balanced: false
- bent: true
- correlation immunity: 0

### `parity_3`

Definition:

`f(x) = popcount(x) mod 2`

Required properties:

- input bits: 3
- algebraic degree: 1
- nonlinearity: 0
- balanced: true
- bent: false
- correlation immunity: 2

### `majority_3`

Definition:

`f(x) = [popcount(x) >= 2]`

This fixture is included as an additional deterministic report row. No scientific claim is attached to its values; CI only requires the executable to complete successfully until explicit expected metrics are frozen in a later calibration revision.

## Candidate identity discipline

A candidate is stored as `(input_bits, exact truth-table bytes)`. A deterministic 64-bit FNV-1a fingerprint is permitted only as an index/bucket key. Hash equality is never accepted as functional equality; exact truth-table comparison is mandatory.

## First equivalence relation

The first canonicalisation implemented by BL-13 is deliberately narrow:

`f ~ g` iff `g = f` or `g = f XOR 1`.

The canonical representative is the lexicographically smaller truth table of a function and its output complement.

This is **not** affine, extended-affine, CCZ, permutation, or input-complement equivalence. Stronger equivalence screens require separate implementations and tests.

## Gate

BL-13.0 passes only when all of the following are green in CI:

1. `cargo fmt --all -- --check`
2. `cargo test --workspace`
3. `cargo clippy --workspace --all-targets -- -D warnings`
4. `cargo run -p booleanlab-discovery --bin bl13_calibrate`

Only after this gate may a Boolean × X generator be promoted from prototype code into the BL-13 candidate pipeline.
