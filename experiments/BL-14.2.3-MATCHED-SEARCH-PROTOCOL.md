# BL-14.2.3 — Matched topology-scoring budget audit

Status at declaration: PROTOCOL / IMPLEMENTATION PENDING.

This is an explicitly exploratory audit of the already observed BL-14.2.2 development panel, NOT a fresh validation, preregistered confirmation, or retuning/replacement of the historical v1 result. The design below is declared before this audit runs. Existing BL-14.1.2 and BL-14.2.2 reports stay unchanged.

## Fixed question

Does a Boolean-induced topology population differ from a direct-mask population when both receive exactly the same number of unique mask evaluations against the same SEARCH labels? Does representing the exact same population directly preserve every selected optimum?

Reuse the unchanged BL-14.2.2 numerical features, training, generators, seeds 0..3, three regimes, and 128 TRAIN / 64 SEARCH / 64 VALIDATION instance partitions. Train once per trial. Audit retained-unit counts 2, 4 and 6 out of 8. These are 36 paired exploratory cells, not independent populations. This audit introduces neither a new model nor final material.

For each trial and retained count k:

1. Freeze three TRAIN-derived predicates per unit: magnitude top-k membership, negative learned readout weight, feature-energy top-k membership. Ties use ascending index. Enumerate all 256 three-predicate functions, materialize through the existing BooleanFunction-to-ExactMask API, group identical k/8 masks, and preserve all generating truth-table codes/functions. Let K be the number of unique masks, not the number of functions.
2. BOOLEAN evaluates each of those K masks once on all 64 SEARCH instances.
3. DIRECT-SAME evaluates the same K mask identities after reconstructing them directly from their retained-index code. It must have bit-identical SEARCH metrics, all selected mask identities and VALIDATION metrics. This is a representation-equivalence control, not an independent discovery arm.
4. DIRECT-MATCHED evaluates K distinct k/8 masks. Seed its population with magnitude top-k (also available in BOOLEAN), then take the first K-1 other masks ordered by descending existing deterministic_random_keys(256, 0xB1140023 + trial.seed), resolving key ties by ascending mask code. Order uses neither SEARCH nor VALIDATION labels. Do not choose among several random orders after seeing outcomes.
5. DIRECT-ALL evaluates all binomial(8,k) masks (28,70,28), retaining every SEARCH optimum. This is an explicit larger-budget diagnostic, never a matched-budget baseline or a validation oracle.
6. Non-search heuristics are dense, magnitude top-k, consecutive unit-level k/2:4 magnitude, and TRAIN activation-energy saliency weight^2 * mean(feature^2). They are reported separately and not claimed to receive K supervised evaluations.

All searches use the same numerical scorer and exactly equal minimum SEARCH task-MSE ties under total_cmp. Keep every tie; never select one on VALIDATION. Freeze all 36 cells before constructing their validation batches. No post-mask refitting, threshold fitting, new observations, retries or seed substitution.

## Accounting and failure rules

Report the full exact candidate-mask population, all Boolean truth-table provenance, K, SEARCH candidate-example evaluations, and aggregate candidate inference multiplications/ReLUs/mask tests. Equal budget means equal UNIQUE TOPOLOGY TASK-SCORING budget only. It does not mean equal controller construction time, Boolean enumeration, training/statistic cost, memory, validation cost, hardware instructions, energy or wall time. Separate the dense reconstruction oracle and scoring arithmetic from the existing limited inference counters. DIRECT-ALL may be used to check subset optimum inequalities on SEARCH, never to pick a VALIDATION winner.

Reject duplicate candidates, wrong mask width/cardinality, empty populations, impossible budgets, malformed partitions and nonfinite metrics. Missing evidence is an error, not zero. Rematerialize frozen Boolean functions before validation to check the observation/rule/mask binding. Validate immutably; changing validation targets may change reported losses only.
