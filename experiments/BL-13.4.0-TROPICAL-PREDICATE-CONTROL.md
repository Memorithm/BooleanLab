# BL-13.4.0 — exact tropical predicate control

Status: implementation/control experiment. No novelty claim.

## Question

Can the BL-13 exact Boolean-function pipeline consume a bounded, deterministic
Boolean × tropical-semiring generator without floating-point thresholds or
heuristic discretisation?

## Frozen semantics

Inputs are four Boolean variables embedded exactly as integers `x_i ∈ {0,1}`.
A max-plus monomial is

```text
c + Σ x_i
```

for its declared variable subset. A tropical polynomial is the exact maximum of
one or more such monomials. The Boolean observation boundary compares two
polynomials using either `>` or `>=`. All arithmetic is checked `i64`; all 16
input rows are exhaustively evaluated.

The initial control family contains four fixed comparisons mixing singleton and
multi-variable monomials. The family is deterministic and is not tuned against
its Boolean metrics.

## Gates

The control is valid only if:

1. hand-computable max-plus reference values match exactly;
2. every generated truth table is exhaustive and accepted by `BooleanFunction`;
3. all four controls are nonconstant and exactly distinct;
4. malformed widths, variable masks and arithmetic overflow fail closed;
5. the exact metrics are produced by the existing SciRust-backed BL-13 metric path.

## Non-claims

Passing this control does not establish novelty, cryptographic usefulness,
superiority over Boolean-only/finite-field/sedenion families, tropical routing
benefit, or hardware performance. Any BL-13.4 discovery claim requires a
separate preregistered search, matched construction/search budgets, declared
equivalence screening (including the stronger vectorial/scalar gates where
applicable), and prior-art review.
