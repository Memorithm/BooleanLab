# BL-14.2.2 — Structured ReLU sparsity across fixed development regimes

Status: PROTOCOL / IMPLEMENTATION PENDING. Numerical development only; no final confirmation or hardware claim. This is a distinct experiment, not a retuning of BL-14.1.2. Its historical negative result and implementation remain unchanged.

## Question and interpretation

Do SEARCH-selected Boolean masks over complete nonlinear units improve validation task MSE relative to competent masks at the same retained-unit budget? Report every cell, including worse/equal results; do not assert a universal benefit or pool these twelve small synthetic cells into a confirmatory statistical claim.

## Frozen design, declared before execution

- Four numerical input dimensions and eight fixed ReLU features. A feature is `max(0, 0.125 + projection_j dot x)`. Projections are the eight signed half-valued rows in the implementation; each has Euclidean norm one.
- The numerical readout has eight coefficients, trained from zero for exactly 512 full-batch gradient steps, step size 1/16, squared-error derivative 2. The feature layer is NOT trained. This is trained nonlinear-feature regression, not end-to-end training of an MLP.
- Evaluator-owned teacher readout `[2,-1,0.5,1.5,-2,0.25,1,-0.5]` over those features; no label noise. The known realizable teacher limits external validity and is never a mask predicate.
- Twelve trials: regimes `isotropic`, `unequal_scale`, `correlated`, each with seeds 0,1,2,3. Counter-based keys reuse BooleanLab's existing deterministic generator with seed `0xB1140022 + seed`. Base coordinates are `(key % 65 - 32)/32`. All regimes share underlying base draws at a given seed; they are paired constructions, not twelve independent populations.
- Isotropic: unchanged four coordinates. Unequal scale: multiply by `[1,2,0.5,0.25]`. Correlated: `[r0,0.75*r0+0.25*r1,r2,0.75*r2+0.25*r3]`.
- Per trial, IDs 0..127 are TRAIN, 128..191 SEARCH, 192..255 VALIDATION. Identity includes regime and seed. Exact split size, unique IDs and trial identity are validated. A finite discrete input distribution may repeat input values; only instance identities are required to be disjoint.
- Train once per trial. Freeze every trial's model, TRAIN-derived predicates, baseline masks and SEARCH selections before constructing any VALIDATION batch. No validation-based refitting, threshold selection, retry, candidate selection or seed replacement.
- Sparsity unit is a whole ReLU feature plus its readout contribution. Every sparse control retains exactly 4/8 units. A rejected unit is skipped BEFORE projection, ReLU and readout multiplication.
- Baselines: dense; global readout magnitude (equal projection norms); 2:4 readout magnitude over consecutive groups of four units; TRAIN activation-energy saliency `readout_weight^2 * mean(feature^2)`; four deterministic random masks (seeds 0..3). Unit-level 2:4 is NOT a claim of NVIDIA sparse-tensor-core weight-layout compatibility.
- Three Boolean predicates, in order: membership in global magnitude top four; negative learned readout weight; membership in TRAIN feature-energy top four. Ranking ties use ascending unit index. No SEARCH or VALIDATION targets enter predicates.
- Exhaustively enumerate all 256 scalar functions on these three predicates and retain exactly 4/8-unit masks. Group identical masks before scoring, retain all generating truth-table codes, and retain all masks with exactly equal minimum SEARCH MSE (`total_cmp`). Equivalent functions/masks are not counted as independent evidence. No additional rule-complexity objective is silently introduced.
