# BL-14.4.1 — Relational Boolean Sparsity on the Trained-Readout ReLU Workload

Status: **PREREGISTERED NUMERICAL DEVELOPMENT / NON-FINAL**

This experiment reuses the BL-14.2.2 fixed-ReLU / trained-readout workload. It does not introduce a second model, open a final holdout, or authorize a hardware-performance claim.

## Question

Can a relation-aware Boolean sparsity policy derived from pairwise activation-state agreement select an exact 4/8 unit mask with lower non-final VALIDATION task MSE than matched independent-score sparse controls?

The experiment studies a controller **inside** the existing numerical model. It does not replace the model with Boolean logic.

## Falsifiable hypotheses

- **H0:** at exact 4/8 retained density, the frozen relation-aware policy does not produce lower non-final VALIDATION task MSE than the best matched independent-score baseline among magnitude, activation-energy, and unit 2:4 on the same trial.
- **H1:** at exact 4/8 retained density, the frozen relation-aware policy produces lower non-final VALIDATION task MSE than that best matched independent-score baseline.

Development decision rule: only consider advancing the mechanism to a separately preregistered final holdout if H1 wins strictly on at least 9 of the 12 declared trials. This rule is an advancement gate, not a statistical significance claim and not a final scientific conclusion.

Dense quality is always reported separately. A relation-aware win against sparse baselines does not imply quality preservation versus dense.

## Fixed trial panel

The panel is inherited unchanged from BL-14.2.2:

- three regimes: `isotropic`, `unequal_scale`, `correlated`;
- four declared seeds per regime: 0, 1, 2, 3;
- 128 TRAIN instances, 64 SEARCH instances, and 64 non-final VALIDATION instances per trial;
- fixed eight ReLU projections;
- trained linear readout with the same 512-step fitting procedure;
- all sparse policies retain exactly 4 of 8 units.

No final holdout is opened in BL-14.4.1.

## Operational relation

For every pair of distinct units `(i, j)`, TRAIN only supplies the integer count

```text
agreement(i, j) = count_x [ (relu_i(x) > 0) == (relu_j(x) > 0) ]
```

across the 128 TRAIN instances. This is an explicit Boolean activation-state relation. It is a **candidate redundancy signal**, not proof of functional equivalence or interchangeable weights.

All 28 undirected pairs are ranked by:

1. descending TRAIN activation-state agreement count;
2. ascending left unit index;
3. ascending right unit index.

For prefix length `k = 1..28`, the first `k` edges define an undirected relation graph. The canonical `booleanlab-core::relational_component_mask` retains the lowest original unit index in each connected component. Only prefixes yielding exactly four retained units are eligible. Duplicate unit masks are deduplicated by exact mask identity, retaining the first prefix that materializes that mask.

This fixes the relation, graph semantics, representative tie-break, retained-density constraint, and ranking tie-break before evaluation.

## SEARCH → FREEZE → VALIDATION

For each of the 12 trials:

1. fit the readout on TRAIN only;
2. compute and rank the 28 pair relations from TRAIN only;
3. enumerate every unique exact 4/8 mask reachable by a ranked relation prefix;
4. score those eligible relation masks on SEARCH only;
5. select minimum SEARCH task MSE, then smaller edge-prefix length, then lower exact mask code as deterministic tie-breaks;
6. freeze the full ranking, selected prefix, exact mask, trained weights, baseline masks, and Boolean baseline before constructing any VALIDATION batch;
7. evaluate the frozen policies on non-final VALIDATION without refitting, reranking, retuning, or selecting a new mask.

VALIDATION evidence must never alter the selected relation prefix or any baseline.

## Required matched controls

Every trial reports through the same scoring path:

- dense;
- magnitude 4/8;
- unit 2:4;
- activation-energy 4/8;
- four fixed density-matched random 4/8 masks;
- the frozen BL-14.2.2 static Boolean winner;
- the frozen BL-14.4.1 relation-aware mask.

The primary H0/H1 comparison uses the best of magnitude, activation-energy, and unit 2:4. Random and static-Boolean rows remain controls and must not be silently discarded.

## Accounting

Sparse admission happens before projection, ReLU, and readout contribution. The inherited reference counters report:

- numerical multiplications;
- ReLU evaluations;
- mask tests.

Relation construction and selection are accounted separately as:

- TRAIN pair tests (`128 × 28` per trial);
- number of unique eligible 4/8 relation masks;
- SEARCH candidate-sample evaluations (`eligible_masks × 64`).

These are deterministic reference counters only. They do not measure elapsed time, memory traffic, HBM residency, bandwidth, energy, or end-to-end speedup.
