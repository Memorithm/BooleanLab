# BL-14.5 — Exact exhaustive / CEGIS search calibration

Scope: **SEARCH-only representation and logical-work calibration**. This is not model, HOLDOUT, latency, energy or GPU evidence.

## Reproduce

```bash
cargo test --locked -p booleanlab-discovery --bin bl14_search_comparison
cargo run --locked -p booleanlab-discovery --bin bl14_search_comparison --release
```

CI runs the tests through the workspace suite and executes the report explicitly. The executable accepts no parameters or external datasets. Output is a commented TSV with schema `bl14.search-comparison.v1`.

## Matched questions

The full exhaustive fit evaluates every function on every supplied row and retains **all** minimum-error ties. CEGIS instead stops at the **first exact** solution in the declared population order. Comparing these directly would conflate different objectives.

The executable therefore adds an independent linear first-exact baseline. It scans candidates in the same integer truth-table order, rejects a candidate on its first mismatching row, and stops at the first exact solution. This matches CEGIS's solution identity and stopping objective.

Full fitting remains the independent correctness oracle. Every report checks that the linear and CEGIS results equal the first zero-error member of that complete fit. Incomplete coverage retains all full-fit ties rather than asserting uniqueness of the CEGIS result.

## Frozen regression controls

For two predicates, the population contains all 16 functions. Predicate 0 is the least significant truth-table address bit.

| Control | Full-fit rule/row decisions | Linear first-exact row checks | CEGIS synthesis row checks | CEGIS verifier row checks | CEGIS total row checks |
| --- | ---: | ---: | ---: | ---: | ---: |
| XOR, full four-row domain | 64 | 14 | 13 | 9 | 22 |
| AND, full four-row domain | 64 | 19 | 9 | 8 | 17 |
| Keep all, full four-row domain | 64 | 30 | 52 | 14 | 66 |

These are exact logical-check counts for the specified implementations and order, not measured instruction counts or elapsed times. The XOR control intentionally shows CEGIS doing **more** logical row checks than the matched linear baseline. The AND control preserves the opposite result. No universal CEGIS advantage is assumed.

The incomplete XOR control supplies only addresses 0, 1 and 2. Full fitting retains codes `0x6` and `0xe`; CEGIS selects the first (`0x6`) without identifying the unobserved output bit.

The contradictory-label control supplies the same predicate row twice with opposite targets. All 16 functions have one mismatch; neither exact-search method has an exact solution. The existing CEGIS failure API does not return failed-run counters, so those fields are `NA`, never zero.

## Differential coverage

Tests compare all 256 three-predicate targets against the complete 256-function population. Each full-domain target has exactly one zero-error truth table. Additional tests cover partial coverage, contradictory labels, arity/shape drift and the existing four-predicate enumeration bound.

## Accounting limits

The report discloses two population-generation passes: one inside the existing exhaustive-fit API and one shared by the linear and CEGIS paths. Population generation, allocations, predicate extraction, metadata validation and memory traffic are not counted as rule/row checks. Full fitting also materializes masks, whereas first-exact paths inspect truth-table outputs directly. Wall-clock performance therefore cannot be inferred from these counts.

The report does not rank rules for model quality, create a new HOLDOUT, modify a frozen predicate schema, or promote a controller. This comparison method may inform TDI-9.3's non-final search experiments; TDI-specific action ordering, observation contracts and final-evaluation boundaries remain owned by TDI.
