# BL-BE2 — representation benchmark protocol

Status: **development measurement infrastructure**. This document does not report a production speedup.

## Purpose

BL-BE2 measures the current Strong-Kleene reference evaluator against BooleanLab's bounded compiled conjunction representations without changing production semantics in ElasticXxx.

The benchmark runner is:

```text
crates/booleanlab-runner/src/bin/bl_be2_repr_bench.rs
```

It has two fixed semantic panels:

- `u64-comparable`: 32 predicates, comparing the generic postfix evaluator, the single-`u64` conjunction, and the multiword conjunction on the same deterministic input corpus;
- `multiword`: 256 predicates, comparing the generic postfix evaluator with the multiword conjunction across four `u64` words per polarity mask.

The literal pattern alternates positive and negative predicates. Inputs are generated by a deterministic SplitMix64 stream from an explicit seed. Every backend is differentially checked against the generic Strong-Kleene oracle before timing. Timed results are also checksum-compared so a semantic divergence fails the run rather than being interpreted as performance evidence.

## Running locally

Use a release build and pin the source commit in the environment:

```bash
BOOLEANLAB_SOURCE_SHA="$(git rev-parse HEAD)" \
  cargo run --locked -p booleanlab-runner --release --bin bl_be2_repr_bench -- 100000 42
```

Arguments are `evaluations` then `seed`. The evaluation count must be in `1..=10000000`.

The output schema is `booleanlab.bl-be2-representation-benchmark.v2`. Each measurement records the panel, backend, arity, generic instruction count, mask words per polarity, evaluation count, elapsed nanoseconds, fixed-point nanoseconds/evaluation (`x1000`), and semantic checksum.

## CI evidence

The main CI workflow executes a bounded 20,000-evaluation smoke campaign on every PR and push to `main`. It stores:

- the raw benchmark report;
- generated `Cargo.lock`;
- `rustc` and `cargo` version output;
- source-head and checkout SHAs;
- runner OS/architecture and GitHub run identity;
- SHA-256 checksums for the evidence files.

The artifact schema is `booleanlab.bl-be2-representation-evidence.v1` and is retained for 90 days by GitHub Actions.

## Claim boundary

The elapsed times are raw wall-clock observations on the executing host. They are not automatically portable across CPUs, runners, builds, operating systems, or workloads. In particular:

- no ratio in this output is a production ElasticXxx speedup;
- hosted-runner timing is not a hardware qualification of a specific Memorithm machine;
- the generic postfix evaluator and compiled conjunctions have different implementation structures, so timing differences require profiling before assigning a mechanism;
- the 32- and 256-predicate panels are synthetic controlled workloads, not model-level sparsity, attention, KV-cache, or end-to-end inference benchmarks;
- energy is not reported because it is not measured;
- resource exhaustion or semantic mismatch is a failed/non-resulting run, not evidence for a backend.

Promotion beyond BooleanLab requires a versioned contract, pinned source commit, reproducible evidence, and independent qualification in the consuming repository.
